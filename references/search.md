# 检索分册：关键词 → 报告 → 选片

> 由 `SKILL.md` 按需加载。只有「帮我查某方向」这类需求才读本文件；纯给 DOI 下载时跳过，直接看 `download.md`。

检索不是终点：**先出一份分析报告，用户看完报告再挑文献**。没有 `_analysis.md` 就不许进检查点。

脚本统一放在 `<技能目录>\scripts\`，下文写作 `$S`（由 `SKILL.md` 的 Glob 规则定位成绝对路径）。下载段见 `download.md`。

本分册自带 `search_multi.mjs` 与 `analyze_pool.mjs`，「关键词 → 候选池 → 分析报告」这一段闭环，不依赖任何第三方检索工具。

## 适用场景

- 用户说「帮我查 X 方向并下载」时
- 已有一批候选文献（有 DOI），需要批量取全文入库时
- 关键词检索完成后，需要先看分析再决定下哪几篇时

## 阶段一：检索与建池

三步按顺序执行，不要跳步，也不要顺手下载。

### 1a 检索

```powershell
node "$S\search_multi.mjs" <候选池.json> --query "关键词" [--concept "a|b|c"] [--exclude "x|y"] [--from 2026] [--to 2026] [--pad 6] [--min-cited 0] [--oa-only] [--top 20] [--email 你的邮箱]
```

- 检索源只有 OpenAlex；Crossref 降级为「印刷期核验 + 元数据补全」，不参与排序
- `--concept` 传概念组，组内用 `|` 给同义词，**跨组必须全部命中**（对齐 OpenAlex 的 AND 语义）。只给 `--query` 时退化为普通关键词检索
- `--exclude` 反向排除，只匹配标题，用来剔除「陶瓷只是添加剂而非基体」这类复合体系
- `--pad` 是必须理解的坑：OpenAlex 的 `publication_date` 常是 online-first 上线日，可能比印刷期早 4~6 个月，会被 `--from` 整批挡掉（曾因此丢掉 4 条高被引）。默认放宽 6 个月，再用 Crossref `published-print` 确认年份，非目标年直接剔除。**窗口收窄时不要关掉它**
- 排序键 = 被引年化 → 期刊档 → 相关度，**没有综合分**。`citedAnnual = cited / max(ageYears, 0.5)`
- `if2y` 取自 OpenAlex 的 `2yr_mean_citedness`，是影响因子的近似量，**不是 JCR 官方 IF**（口径不同，常差 0.5~2），对外只能写「IF≈」
- 输出 `pool.json` 与 `_search_report.json`（去重、主题门控、pad 核验的原始数字，1c 要读它）

同年新刊的陷阱：53 条全在 2026 年时，`ageYears` 全被折到 0.5，年化退化成「被引×2」，零被引条目整体沉底。这是 1c 必须单列「零被引·高影响刊」的原因，不是排序键能修好的。

已有检索工具时（`nature-literature-pipeline`、Scopus、Web of Science 导出等）也可以，候选池至少要含 `doi` / `title` / `journal` / `year` / `cited` / `oa`，并尽量补 `citedAnnual` / `tier` / `if2y`，否则 1c 的统计会缺项。

### 1b 元数据补全

```powershell
node "$S\enrich_meta.mjs" <候选池.json> <候选池_enriched.json>
```

- 补 `publisher` / `host` / `pii`，并顺带生成 `meta.json`（校验关键词与缺省文件名）
- 补 `pubDate` / `pubPrintYear`，**印刷期优先**：Elsevier / Wiley 的 `issued` 常是上线年，按它算会把 2026 见刊的文章记成 2025
- 补 `absText` / `absSrc`，三源兜底 Crossref JATS → Semantic Scholar → OpenAlex（OpenAlex 摘要默认截断到 600 字）
- 仍有约 40% 的 Elsevier 新刊拿不到摘要（ScienceDirect 403 挡爬虫），这些会进 1c 的「四、暂缺摘要的文献」，**只凭标题判断，不许编评语**
- 之后一律使用 enriched 版本

### 1c 分析（检查点前置）

```powershell
node "$S\analyze_pool.mjs" <候选池_enriched.json> [--report _search_report.json] [--top 15] [--clusters 5]
```

产出 `_analysis_draft.md`（只含可计算事实，结论处全是 `_(待填)_`）与 `_analysis_stats.json`。

**脚本只算数，语义判断由你写。** 必须把 draft 补成同目录的 `_analysis.md`，这是进检查点的硬性前提：

| 章节 | 谁写 | 要求 |
| --- | --- | --- |
| 一、文献来源与筛选 | 脚本 | 「总体判断」由你填 |
| 二、研究方向的谱系划分 | 脚本给聚类与主题词，**由你划分** | 聚类只是线索；同题文献标题高度雷同，必须按摘要内容自行划直接相关 / 边缘 / 无关 |
| 2.4 高影响力期刊的近期零被引文献 | 脚本自动 | 已单列（期刊档 → IF≈ → 相关度），不许删；进了第三节评述的带 ✅ |
| 三、代表性文献评述 | **你写** | 💡核心贡献 / 🔬方法 / 📊主要结果（**必须带数值**，没有就写「摘要未给数值」）/ 🧭评述。无摘要条目一律不写评语 |
| 四、暂缺摘要的文献 | 脚本列清单 | 只能写「凭标题推测的线索」，并标明置信度低 |
| 五、相关性存疑与研究边界 | 脚本列清单 | 低被引 / 主题偏僻往往是空白点线索，不要当作无关内容丢弃 |

**报告骨架（定稿，目录与标题不得改名；一级标题只写主题名，不带「研究进展」，年份括注另起一行）：**

```markdown
（<起始年>-<结束年>年文献调研）

> 文献范围：…（online-first 经印刷期复核）

```

三条硬规则：

1. 术语黑名单：`速读卡`、`噪声`、`池子`、`候选池分析`、`子体系全景` 一律不出现在 `_analysis.md` 里
2. 每条评述必须写出局限，只夸不批视为未完成
3. 收尾必须回答「若只选 5 篇是哪 5 篇」：A 组 >5 篇时从 A 里砍掉与同组重复度最高的一篇；A 组 ≤5 篇时写「共 N 篇，全部必读，无需再筛」，不许硬凑到 5

生成后自检：标题与骨架一致 / 每条有 DOI / A 组有推荐理由 / 有问题陈述 / 黑名单词零出现 / 结尾有「若只选 5 篇」。六项要**逐项打勾写进对话正文**（例：骨架 ✅｜DOI ✅｜A 组理由 ✅｜问题陈述 ✅｜黑名单 0 ✅｜五篇结论 ✅），缺项不许进检查点。

自检通过后导出 Word 版（便于发给导师或存档）：

```powershell
python "$S\md2docx.py" <输出目录>\_analysis.md
```

产出同目录 `_analysis.docx`，保留标题层级、列表、表格、加粗 / 斜体 / 行内代码。版式：A4、页边距 2.54 cm，正文宋体小四（12 pt，可用环境变量 `MD2DOCX_BODY_PT` 临时改字号）、首行缩进两字，标题黑体、一级标题居中且其下另起一行写「（<年份>年文献调研）」；表格固定列宽，总宽等于版心 15.92 cm，按内容分配且保证每个英文单词不被折断，表头加粗居中并跨页重复，单元格内容居中（DOI 列左对齐，避免长串被挤成多行）、垂直居中；化学式数字与 Unicode 上下标一律转为真正的上下标；页脚居中「第 X 页」。缺 `python-docx` 时只打印一行提示，**不阻塞检查点**（先 `pip install python-docx`）。


验收标准：用户**只看这份报告就能决定下哪几篇**。每条要有期刊档、IF≈、被引、日期、获取性预判（直取 / 走浏览器）；A 组 4–8 篇并给出明确推荐理由；报告结尾直接回答「若只选 5 篇是哪 5 篇」。

## 阶段三：生成清单

- 只需给出 DOI（或文章页 URL），文件名交给 `enrich_meta.mjs` 按 `{年}_{首作者}_{DOI后缀}.pdf` 生成
- 想自定义命名时再写 `file` 字段
- 最省事的做法是把选中的条目从候选池里切出来写成 JSON：`run_batch.ps1` 的 `-Items` 接受 JSON 数组，也接受纯 DOI 文本，两种都会先过 normalize

## 阶段四：下载（一键）

```powershell
& "$S\run_batch.ps1" -Out <输出目录> -Items <dois.txt|items.json> -Email <真实邮箱> [-Kb <IMA知识库ID>] [-SkipIma]
```

它依次做 normalize → enrich → oa_route → dispatch → verify，自己启动 Edge 并等端口，因此不受「同一条 Shell 命令」约束影响。产出 `_oa_report.json`、`_browser_pending.json`、`_failed.json`、`_verify_report.json`、`_index.json`。

- `-Email` 只用于 Unpaywall 与 Crossref 的礼貌池；不传则仅用 OpenAlex，OA 直取命中率会下降。Unpaywall 不接受 `example@` 这类示例邮箱
- `-Kb <IMA知识库ID>` 可选：校验通过后把 PDF 再复制一份进 IMA 知识库，台账 `_ima_uploaded.json` 防重复。前提是本机已装 `ima-skill` 且有 `~/.config/ima/client_id` 与 `api_key`（或环境变量 `IMA_OPENAPI_CLIENTID` / `IMA_OPENAPI_APIKEY`）；PDF 先经腾讯云 COS 再入库，机构对上传有合规限制时不要开
- `-SkipIma` 显式关掉上传；缺依赖或缺 ID 时脚本自身也只 WARN 跳过，不改变退出码，本地 PDF 始终保留

先预演一次更稳妥：`-Dry` 不起浏览器、只在 dispatch 打印分派结果，能提前看到有哪几篇会落 `unknown`、每个通道各几篇。

需人工介入的两种情况：

- `dispatch` 打印 `WARN ... kind=unknown`：候选池缺 `publisher` / `host`，需人工指定通道
- `_failed.json` 非空：修复后 `-Retry` 只重跑失败条目；再加 `-Reuse` 可跳过 normalize / enrich，不再打 Crossref

## 阶段五：校验与归档

1. 阶段四已自动跑批量校验（`-SkipVerify` 可跳过），也可单独重跑：

```powershell
python "$S\verify_pdf.py" <输出目录> --meta <输出目录>\meta.json
```

2. 读取 `_verify_report.json`，任一 FAIL 必须回报，不得当作成功
3. 写/更新 `文献清单.md`：编号、年份、期刊、标题、DOI、被引、PDF 文件名、校验结果（PASS/FAIL + 页数 / 大小）；有 `_analysis.md` 时再加一列「第三节评述结论」

> `verify_pdf.py` 会扫描整个 `-Out` 目录，存量文献也会一并列出。判断本次新增请看 `_index.json` 与 `文献清单.md`，不要用 PASS 总数当成本批下载数。

- 检查点的两个问题、全部选项与默认值必须先写进对话正文，弹窗不能是信息的唯一载体
- `AskUserQuestion` 只弹一次；被跳过就转文字待命，不重弹、不代用户拍板
- `_analysis.md` 未生成，不许问「下哪些」——不许拿 `pool.json` 的排序表直接当分析

- 下载阶段遵守 `download.md` 的硬约束（同一条 Shell 命令、单篇间隔）
